# Rain Drop: โปรแกรมดูแลและควบคุมเครื่องในเครือข่าย (Prototype)

โปรแกรมดูแลและควบคุมเครื่องในเครือข่าย เขียนเองด้วย C# / .NET 8 (WinForms) สำหรับ Windows

| ควบคุมเมาส์/คีย์บอร์ดระยะไกล (ดับเบิลคลิกที่ภาพ) | ✅ |
| ล็อกหน้าจอ, ปลดล็อก, ส่งข้อความ popup | ✅ |

## โครงสร้าง

ทุกอย่างอยู่ที่รากรีโป (ไม่มีโฟลเดอร์ `RainDrop/` ซ้อนอีกชั้น)

```
├─ Core/         โพรโทคอล/ตรรกะที่ไม่ผูก Windows (net8.0 ล้วน): รูปแบบแพ็กเก็ต, MsgType + record ข้อความ,
│                HubProtocol, Discovery, การเซ็น/ตรวจ ECDSA — คง namespace เดิม RainDrop.Shared
├─ Shared/       โค้ด UI/เสียงที่ใช้ร่วมกัน (WinForms): หน้าต่างแชท, ตัวอัดเสียง, คอลเสียง, ธีม, HubClient
│                (อ้างอิง Core สำหรับโพรโทคอล แทนการมีโค้ดซ้ำ)
├─ Agent/        ติดตั้งบนเครื่องลูก: TCP server, จับภาพจอ, จำลองอินพุต, ล็อกจอ, ไอคอนถาดระบบ
├─ AgentService/ Windows Service (สิทธิ์ SYSTEM) คอยเปิด Agent ตอนบูต/ปลุกกลับ + บล็อกเว็บผ่าน hosts
├─ Hub/          เซิร์ฟเวอร์กลางของห้องชุมชน (แชทกลุ่ม/คอลเสียง/แชร์ไฟล์)
├─ Master/       ติดตั้งบนเครื่องผู้ดูแล: หน้าจอรวม + หน้าต่างควบคุม
├─ Tests/        เทสต์ xunit ของ Core (round-trip โพรโทคอล, เซ็น/ตรวจ ECDSA, เฟรมเสียง/ชังก์ไฟล์)
├─ assets/       ไอคอนหยดน้ำ (raindrop.ico)
├─ installer/    สคริปต์ Inno Setup ของตัวติดตั้งทั้งสองตัว
├─ .github/workflows/ci.yml   CI บน windows-latest: build Release + test
├─ build-installer.bat        สร้างตัวติดตั้งสำเร็จรูป
├─ build.bat                  build อย่างเดียว
└─ install-agent.ps1          ติดตั้งเครื่องลูกด้วยสคริปต์แทนตัวติดตั้ง
```

```
 Master (ผู้ดูแล)                         Agent (เครื่องลูก, พอร์ต TCP 11400)
 ─────────────────                        ───────────────────────────────
 1. connect ──────────────────────────►
                ◄──────────────────────── 2. AuthChallenge (nonce สุ่ม 32 ไบต์)
 3. AuthResponse (เซ็น nonce ด้วย private key) ►
                ◄──────────────────────── 4. AuthResult (ตรวจด้วย public key)
 5. ScreenRequest ────────────────────►
                ◄──────────────────────── 6. ScreenFrame (JPEG)
 7. Mouse/Key/Lock/Message/Power/Run ─►   (ไม่มีการตอบกลับ)
 8. ChatMessage / VoiceMessage ◄────────► ส่งได้ทั้งสองทางทุกเมื่อ
```

แพ็กเก็ต = `[1 ไบต์ชนิด][4 ไบต์ความยาว][payload]` โดย payload ของคำสั่งเป็น JSON และของภาพหน้าจอเป็น JPEG

## ตัวติดตั้งสำเร็จรูป (แนะนำ)

### สร้างตัวติดตั้ง (ทำครั้งเดียวบนเครื่องผู้พัฒนา)

1. ดับเบิลคลิก **`build-installer.bat`** (ถ้ายังไม่มี .NET 8 SDK หรือ Inno Setup สคริปต์จะติดตั้งให้ผ่าน winget)
2. จะได้ไฟล์ 2 ตัวในโฟลเดอร์ `installer-output`

| ไฟล์ | ติดตั้งที่ | หมายเหตุ |
|---|---|---|
| `RainDrop-Master-Setup.exe` | เครื่องผู้ดูแล | ไม่มีกุญแจฝังอยู่ Master สร้างกุญแจเองตอนเปิดครั้งแรก |
| `RainDrop-Agent-Setup.exe` | เครื่องลูกทุกเครื่อง | ไม่ฝังกุญแจ ผู้ติดตั้งเลือก enrollment bundle (`.rdrop`) เฉพาะเครื่อง ใส่รหัส bundle และตั้งรหัสผู้ดูแล |

สคริปต์ build **ไม่สร้างหรือฝังกุญแจลับ** Master สร้างกุญแจเองตอนเปิดครั้งแรกและเก็บเข้ารหัส DPAPI (CurrentUser)
ที่ `%AppData%\RainDrop` ได้แก่ `master-private.dpapi` (กุญแจ challenge C1), `ca-private.dpapi` (CA ขององค์กร),
`master-client-private.dpapi` (ใบรับรอง client ของ Master) และ `pki-state.dpapi` (ทะเบียนเครื่อง/รายการเพิกถอน)

การเตรียมเครื่องลูกแบบ C2a (ใช้ enrollment bundle แทน `master-public.pem`):
1. เปิด Master ครั้งแรก (สร้าง CA อายุ 10 ปี และใบรับรอง Master อัตโนมัติ)
2. เมนู **เพิ่มเติม → ส่งออก enrollment bundle** ใส่ชื่อเครื่องลูกให้ตรงกับชื่อ Windows, IP/ชื่อโฮสต์ที่ใช้เชื่อมต่อ
   และรหัส bundle อย่างน้อย 12 ตัวอักษร จะได้ไฟล์ `.rdrop` เฉพาะเครื่องนั้น
   หรือใช้ CLI: `RainDrop.Master.exe --export-enrollment <ชื่อเครื่อง> <IP คั่นด้วยจุลภาค> <ไฟล์.rdrop>`
3. ตอนติดตั้ง Agent เลือกไฟล์ `.rdrop` และใส่รหัส bundle (หรือส่ง `/BUNDLE=` และ `/BUNDLEPASSWORD=` ในโหมดเงียบ)
4. สำหรับ Hub (ยังไม่อยู่ใน C2a): ยังใช้ `master-public.pem` เดิม วางที่ `keys\master-public.pem` ก่อน build
   สคริปต์จะคัดลอกเป็น `publish\Hub\hub-key.pem` ให้ถ้าพบ

> **สำรองโฟลเดอร์ `%AppData%\RainDrop` ไว้ในที่ปลอดภัย** ไฟล์ `.dpapi` ถอดรหัสได้เฉพาะบัญชี Windows เดิมบนเครื่องเดิม
> ถ้า CA หาย ต้องสร้างใหม่และ enroll เครื่องลูกใหม่ทั้งหมด

### ติดตั้ง

- **เครื่องผู้ดูแล:** ดับเบิลคลิก `RainDrop-Master-Setup.exe` แล้วกด Next ไปจนจบ เปิดโปรแกรมแล้ว**เครื่องลูกในวงแลนเดียวกันจะขึ้นมาเองภายในไม่กี่วินาที**
  (ค้นหาซ้ำทุก 30 วินาที เครื่องที่เพิ่งติดตั้งก็จะขึ้นมาเอง และถ้า IP ของเครื่องลูกเปลี่ยน ระบบจะอัปเดตให้)
- **เครื่องลูก:** ดับเบิลคลิก `RainDrop-Agent-Setup.exe` แล้วกด Install ตัวติดตั้งจะบังคับให้
  **ตั้งรหัสผ่านผู้ดูแล (อย่างน้อย 8 ตัวอักษร ไม่มีค่าเริ่มต้น)** และ **เลือกไฟล์ `.rdrop` พร้อมรหัส bundle** ที่ได้จากเครื่อง Master
  จากนั้นติดตั้ง ตั้งค่าไฟร์วอลล์ (ทุกประเภทเครือข่าย) ตั้งให้เปิดอัตโนมัติ และเริ่มทำงานทันที (จะเห็นไอคอนรูปโล่ที่มุมขวาล่าง)
- **ติดตั้งหลายเครื่องพร้อมกันแบบไม่มีหน้าต่าง** (ใช้กับ Group Policy, PDQ Deploy, Intune หรือสคริปต์)
  ต้องส่ง `/PASSWORD=`, `/BUNDLE=` และ `/BUNDLEPASSWORD=` มิฉะนั้นตัวติดตั้งจะล้มเหลวทันที:
  ```
  RainDrop-Agent-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /PASSWORD=MyStrongPass123 /BUNDLE=C:\deploy\PC-01.rdrop /BUNDLEPASSWORD=MyBundlePass12
  ```
- **ถอนการติดตั้ง:** Settings → Apps → Installed apps → Rain Drop Agent / Rain Drop Master → Uninstall

ถ้า Windows ขึ้นหน้าจอ "Windows protected your PC" ให้กด **More info → Run anyway**
(ขึ้นแบบนี้เพราะตัวติดตั้งยังไม่ได้ลงลายเซ็นดิจิทัล ถ้าบริษัทมีใบรับรอง Code Signing ใช้เซ็นไฟล์ได้เลย)

ตัวติดตั้งทั้งสองตัวจะเปิดสิทธิ์ไมโครโฟนให้ด้วย เพื่อให้ส่งข้อความเสียงได้ทันที (ยกเว้นบริษัทปิดไว้ด้วย Group Policy)

เครื่องลูกที่อยู่คนละวงเครือข่าย (ข้ามเราเตอร์/VLAN) การค้นหาอัตโนมัติจะไปไม่ถึง ให้กด **"เพิ่มเครื่องเอง"** แล้วใส่ IP

เครื่องลูกจะเริ่ม Agent เองทุกครั้งที่บูต และถ้าผู้ใช้กด End Task ระบบจะปลุกกลับภายในไม่กี่วินาที (ดูหัวข้อ "การบังคับให้ Agent ทำงานเสมอ")

ค่าตั้งของ Master (รายชื่อเครื่อง) เก็บไว้ที่ `%AppData%\RainDrop` ของผู้ใช้แต่ละคน

## วิธี Build แบบไม่ทำตัวติดตั้ง

ต้องมี **.NET 8 SDK** บน Windows (หรือเปิด `RainDrop.sln` ด้วย Visual Studio 2022)

```bat
build.bat
```

ผลลัพธ์อยู่ที่ `publish\Agent\RainDrop.Agent.exe` และ `publish\Master\RainDrop.Master.exe`
(build แบบ self-contained จึงไม่ต้องติดตั้ง .NET Runtime บนเครื่องลูก)

### บิลด์ทั้งโซลูชันและรันเทสต์

โปรเจกต์ WinForms (Shared/Agent/Master/Hub) เป็น `net8.0-windows` จึงต้องบิลด์บน **Windows**
ส่วน `Core` และ `Tests` เป็น `net8.0` ล้วน ไม่ผูก Windows (บิลด์/เทสต์บนแพลตฟอร์มใดก็ได้ที่มี .NET 8 SDK)

```bat
dotnet build -c Release
dotnet test Tests/Tests.csproj -c Release
```

CI (`.github/workflows/ci.yml`) รันสองคำสั่งนี้บน `windows-latest` ทุกครั้งที่ push หรือเปิด PR
(ไม่ตั้งค่า code signing เพราะยังไม่มีใบรับรอง)

## ติดตั้งเองแบบไม่ใช้ตัวติดตั้ง

1. **เปิด Master ครั้งแรก** แล้วส่งออก enrollment bundle ของเครื่องลูกจากเมนู **เพิ่มเติม**
2. **ติดตั้ง Agent บนเครื่องลูก**: คัดลอกโฟลเดอร์ `publish` และไฟล์ `.rdrop` ไปที่เครื่องลูก แล้วเปิด PowerShell แบบ Administrator:
   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\install-agent.ps1 -Bundle .\PC-01.rdrop -BundlePassword MyBundlePass12 -Password MyStrongPass123
   ```
   สคริปต์ติดตั้งที่ `C:\Program Files\RainDrop\Agent`, เปิดไฟร์วอลล์พอร์ต 11400 และตั้งให้ทำงานอัตโนมัติ
   identity ของ Agent ถูกเก็บใน `%ProgramData%\RainDrop\private` ซึ่งผู้ใช้ทั่วไปอ่าน/เขียนไม่ได้
3. ที่ Master กด **เพิ่มเครื่อง** แล้วใส่ IP ของเครื่องลูก ภาพหน้าจอจะขึ้นภายในไม่กี่วินาที
4. วิธีใช้งาน:
   - **คลิก** ที่ภาพเพื่อเลือกเครื่อง (กรอบเป็นสีฟ้า) ถ้าไม่เลือกเลย คำสั่งจะส่งไป **ทุกเครื่อง**
   - **ดับเบิลคลิก** เพื่อเปิดหน้าต่างควบคุม แล้วกด **"โหมดควบคุม"** ก่อนจึงจะใช้เมาส์/คีย์บอร์ดได้
   - **คลิกขวาแล้วเลือก "แชท"** (หรือเลือกเครื่องแล้วกดปุ่ม "แชท") เพื่อคุยกับเครื่องนั้น

## การแชท

| | เครื่องแม่ (Master) | เครื่องลูก (Agent) |
|---|---|---|
| เริ่มแชท | คลิกขวาที่ภาพ แล้วเลือก "แชท" | ดับเบิลคลิกไอคอนรูปโล่ใน Tray หรือคลิกขวาแล้วเลือก "แชทกับผู้ดูแลระบบ" |
| เมื่อมีข้อความเข้า | หน้าต่างแชทของเครื่องนั้นเปิดขึ้นเอง กะพริบที่ Taskbar และกรอบภาพเป็น **สีส้ม** จนกว่าจะเปิดอ่าน | หน้าต่างแชทเด้งขึ้นมาอยู่ข้างหน้าสุดทันที |
| ประวัติ | ปิดหน้าต่างแล้วประวัติยังอยู่ (แต่หายเมื่อปิดโปรแกรม) | เหมือนกัน |

### ข้อความเสียง

1. ในหน้าต่างแชท กดปุ่ม **"● อัดเสียง"** แล้วพูด (ปุ่มจะเป็นสีแดงพร้อมแสดงเวลาที่อัดไปแล้ว)
2. กด **"■ หยุดและส่ง"** เพื่อส่ง หรือกด **"ยกเลิก"** เพื่อทิ้งเสียงที่อัดไว้ (อัดได้สูงสุด 2 นาที ครบแล้วจะส่งให้อัตโนมัติ)
3. อีกฝั่งจะเห็นปุ่ม **"▶ ข้อความเสียง 0:05"** กดเพื่อฟัง และกดอีกครั้งเพื่อหยุด
4. **คลิกขวา** ที่ปุ่มข้อความเสียงเพื่อบันทึกเป็นไฟล์ `.wav`

รายละเอียดทางเทคนิค: อัดเสียงด้วย MCI (`winmm.dll`) และเล่นด้วย `SoundPlayer` ซึ่งมีอยู่แล้วใน Windows ไม่ต้องติดตั้งไลบรารีเพิ่ม
เสียงเป็น WAV 16 kHz mono ขนาดประมาณ 32 KB ต่อวินาที (1 นาทีประมาณ 2 MB)

> **ต้องเปิดสิทธิ์ไมโครโฟน:** Settings → Privacy & security → Microphone → เปิด **"Let desktop apps access your microphone"**
> ถ้าปิดไว้ ระบบจะขึ้นข้อความ "อัดเสียงไม่ได้" ในหน้าต่างแชท

ปุ่ม **"ส่งข้อความ (popup)"** ยังมีอยู่ ใช้ประกาศถึงหลายเครื่องพร้อมกันแบบไม่ต้องตอบกลับ

## แก้ปัญหาเชื่อมต่อไม่ได้

**1. ดูข้อความบนกรอบภาพในหน้าจอ Master** ซึ่งจะบอกสาเหตุไว้

| ข้อความ | สาเหตุ / วิธีแก้ |
|---|---|
| หมดเวลา: IP ผิด, เครื่องปิดอยู่ หรือไฟร์วอลล์... | ตรวจ IP / ไฟร์วอลล์เครื่องลูก (ดูข้อ 2) |
| เครื่องลูกปฏิเสธการเชื่อมต่อ: Agent ไม่ได้ทำงาน | ที่เครื่องลูกไม่มีไอคอนโล่ ให้เปิดโปรแกรม หรือตรวจว่าแอนตี้ไวรัสบล็อกหรือไม่ |
| TLS ปฏิเสธการเชื่อมต่อ | ใบรับรองหมดอายุ/ถูกเพิกถอน/ไม่ใช่ CA เดียวกัน หรือชื่อเครื่องไม่ตรงกับที่ enroll ไว้ ให้ enroll ใหม่ |
| กุญแจไม่ตรงกัน | กุญแจ challenge ชั้นที่สองไม่ตรง ให้ใช้ bundle จาก Master นี้ |
| ติดต่อเครื่องนี้ไม่ได้: อยู่คนละวงเครือข่าย | สองเครื่องต้องอยู่ในวงเครือข่ายที่ติดต่อกันได้ |

**2. รันสคริปต์ตรวจสอบบนเครื่องลูก** (ติดตั้งมาพร้อม Agent แล้ว) ใน PowerShell แบบ Administrator:
```powershell
Set-ExecutionPolicy -Scope Process Bypass
& "C:\Program Files\RainDrop\Agent\diagnose-agent.ps1" -Fix
```
สคริปต์จะตรวจว่า Agent ทำงานอยู่หรือไม่, เปิดพอร์ตแล้วหรือยัง, ไฟร์วอลล์และประเภทเครือข่าย, ไฟล์กุญแจ, แสดง IP ของเครื่อง และแก้ให้อัตโนมัติเมื่อใส่ `-Fix`

**3. เทียบลายนิ้วมือกุญแจ** ที่ Master กด "ตั้งค่า / กุญแจ" และที่เครื่องลูก คลิกขวาไอคอนโล่ → "สถานะการเชื่อมต่อ"
ค่าที่แสดงต้องตรงกัน (เช่น `3F:A1:9C:...`)

**4. ทดสอบจากเครื่องแม่:** `Test-NetConnection <IP เครื่องลูก> -Port 11400`
ถ้าเครื่องลูกผ่านทุกข้อแต่ยังได้ `False` แสดงว่ามีอุปกรณ์เครือข่ายกั้นอยู่ เช่นอยู่คนละ VLAN หรือ Wi-Fi เปิด Client/AP Isolation

## แจ้งเตือน และ บล็อกโปรแกรม/เว็บ

### แจ้งเตือนเรียลไทม์ (เปิด-ปิดได้)

เมื่อเครื่องลูกมีเหตุการณ์ Agent จะส่งแจ้งเตือนมาที่ Master ทันที (ไม่ต้องรอ poll) แล้ว Master เด้งการ์ดแจ้งเตือนมุมขวาล่าง + ไอคอนถาดระบบ:
- **เสียบ USB** — "เสียบ USB: E:\ (ชื่อไดรฟ์)"
- **ส่งไฟล์ออก / ดาวน์โหลด** — บอกชื่อไฟล์
- **บล็อกโปรแกรม** — เมื่อปิดโปรแกรมที่ถูกบล็อก

เปิด/ปิดการแจ้งเตือนได้ที่ปุ่ม **"⋯ เพิ่มเติม → การแจ้งเตือน: เปิด/ปิด"** และดูย้อนหลังที่ **"ดูการแจ้งเตือนล่าสุด"** (ค่าตั้งนี้จำไว้)

### บล็อกโปรแกรม / เว็บ (รายเครื่อง)

เลือกเครื่อง (หรือหลายเครื่อง) แล้วกดปุ่ม **"🚫 บล็อก"** (หรือ ⋯ → บล็อกโปรแกรม/เว็บ) ใส่

- **ชื่อโปรแกรมที่ห้ามเปิด** บรรทัดละชื่อ เช่น `chrome`, `game.exe`, `LINE` — Agent จะปิดโปรแกรมนั้นทันทีถ้าเปิดขึ้น (ตรวจทุก 2 วินาที) และแจ้งเตือนกลับ
- **เว็บ/ลิงก์ที่ห้ามเข้า** บรรทัดละรายการ เช่น `facebook.com`, `youtube.com` — บล็อกโดยการแก้ไฟล์ `hosts` (ชี้โดเมนไป 0.0.0.0) ซึ่งทำโดย **Windows Service สิทธิ์ SYSTEM** เพราะการแก้ hosts ต้องใช้สิทธิ์ผู้ดูแล

รายการบล็อกถูกจำไว้ที่ Master และส่งซ้ำทุกครั้งที่เครื่องลูกเชื่อมต่อใหม่ จึงคงอยู่แม้รีสตาร์ท

**ข้อควรรู้**
- การบล็อกเว็บต้องติดตั้ง Agent แบบมี Service (ตัวติดตั้ง `RainDrop-Agent-Setup.exe`) ถ้าติดตั้งแบบสคริปต์ที่ไม่มี Service จะบล็อกได้เฉพาะโปรแกรม
- บล็อกเว็บด้วย hosts เป็นการบล็อกระดับโดเมน (ทั้งโดเมนและ www.) ไม่ได้บล็อกเฉพาะหน้า และไม่กันการเข้าผ่าน IP ตรง ๆ หรือ DNS-over-HTTPS ของบางเบราว์เซอร์ — สำหรับการบล็อกที่รัดกุมกว่านี้ต้องใช้ไฟร์วอลล์/พร็อกซีระดับเครือข่าย
- เมื่อถอนการติดตั้งหรือ Service หยุดอย่างถูกต้อง ระบบจะล้างรายการบล็อกเว็บออกจาก hosts ให้

## ตรวจสอบกิจกรรมการใช้งาน (แยกรายเครื่อง)

ที่หน้าต่าง Master เลือกเครื่อง แล้วกดปุ่ม **"📊 กิจกรรม"** (หรือคลิกขวาที่ช่องเครื่อง → "ดูกิจกรรม") จะเปิดหน้าต่างกิจกรรมของเครื่องนั้น ดึงข้อมูลสดทุก 2 วินาที แสดง

- **โปรแกรมที่กำลังแอคทีฟ** (หน้าต่างที่โฟกัสอยู่) พร้อมชื่อหน้าต่าง — อัปเดตเรียลไทม์
- **เวลาที่ใช้แต่ละโปรแกรม** (นับวินาทีที่โปรแกรมนั้นเป็นหน้าต่างแอคทีฟ ตั้งแต่ Agent เริ่มทำงาน) เรียงมากไปน้อย โปรแกรมที่แอคทีฟอยู่ตอนนี้เป็นสีเขียว
- **โปรแกรมที่เปิดอยู่** (โปรแกรมที่มีหน้าต่าง)
- **ไฟล์ที่ดาวน์โหลด / ส่งออก**: ไฟล์ใหม่ในโฟลเดอร์ Downloads นับเป็น "ดาวน์โหลด", ไฟล์ที่ถูกคัดลอกลงไดรฟ์ USB นับเป็น "ส่งออก (USB)"

**วิธีวัดเวลา:** Agent จับหน้าต่างที่แอคทีฟ (foreground) ทุก 1 วินาที แล้วบวกเวลาให้โปรแกรมนั้น จึงเป็น "เวลาที่ผู้ใช้กำลังจดจ่อกับโปรแกรม" ไม่ใช่แค่เวลาที่โปรแกรมเปิดค้างไว้

**ข้อจำกัดของการตรวจไฟล์:** จับได้เฉพาะไฟล์ที่ลงโฟลเดอร์ Downloads และไฟล์ที่คัดลอกลง USB เท่านั้น ยังไม่จับการอัปโหลดขึ้นเว็บ/คลาวด์ หรือแนบไฟล์ในอีเมลโดยตรง (ต้องดักระดับเครือข่ายซึ่งซับซ้อนกว่านี้มาก) และข้อมูลเวลาใช้งานจะรีเซ็ตเมื่อ Agent เริ่มทำงานใหม่ (ยังไม่เก็บลงไฟล์ถาวร)

> **PDPA:** การเก็บว่าผู้ใช้เปิดโปรแกรมอะไร นานแค่ไหน และโหลด/ส่งไฟล์อะไร เป็นการเฝ้าสังเกตที่ละเอียดอ่อนมาก ต้องแจ้งและขอความยินยอมจากผู้ใช้ก่อน และใช้เท่าที่จำเป็นตามนโยบายองค์กร

## ห้องชุมชน (แบบ Discord)

เป็นระบบแยกจากการควบคุมหน้าจอ ใช้ "เซิร์ฟเวอร์กลาง" (Hub) ที่ทุกเครื่องต่อเข้ามา ทั้งผู้ดูแลและเครื่องลูกเข้าร่วมได้เหมือนกัน

**ความสามารถ**
- **ห้องแชทกลุ่มหลายช่อง** (เช่น ทั่วไป/ประกาศ/ขอความช่วยเหลือ) เก็บประวัติล่าสุดให้คนเข้าทีหลังเห็น
- **คอลเสียงสด** หลายคนพร้อมกัน เข้า/ออกห้องเสียงได้ กดปิดไมค์ได้ (ใช้ NAudio)
- **แชร์ไฟล์/รูปภาพ** รูปแสดงในแชทเลย ไฟล์อื่นกดเปิด/บันทึกลง `Downloads\RainDrop`
- **รายชื่อ+สถานะออนไลน์** เห็นว่าใครออนไลน์ ใครอยู่ในห้องเสียงไหน

**เปิดเซิร์ฟเวอร์กลาง (Hub)** บนเครื่องที่เปิดตลอด (เครื่องผู้ดูแลหรือเซิร์ฟเวอร์):
- หลัง build จะได้โฟลเดอร์ `publish\Hub` — คลิกขวา `run-hub.bat` → Run as administrator (เปิดไฟร์วอลล์พอร์ต 11500 ให้ด้วย)
- หรือดับเบิลคลิก `RainDrop.Hub.exe` ตรง ๆ (ต้องเปิดพอร์ต 11500 เอง)
- Hub อ่านลายนิ้วมือชุมชนจาก `hub-key.pem` (คัดลอกจาก `master-public.pem` ที่ export จาก Master) เฉพาะเครื่องที่ใช้กุญแจชุดเดียวกันเท่านั้นจึงเข้าร่วมได้

**เข้าใช้งาน**
- **ผู้ดูแล:** ในหน้าต่าง Master กดปุ่ม "ชุมชน (แชท/คอลเสียง)" ครั้งแรกจะถามที่อยู่เซิร์ฟเวอร์ (IP ของเครื่องที่รัน Hub)
- **เครื่องลูก:** คลิกขวาไอคอนหยดน้ำ → "เปิดห้องชุมชน" (ตั้งที่อยู่เซิร์ฟเวอร์ตอนติดตั้งด้วย `/HUB=` หรือกรอกในหน้าตั้งค่าของตัวติดตั้ง)

> คอลเสียงเป็นส่วนที่ซับซ้อนและยังไม่ได้ทดสอบบนเครื่องจริง ถ้าเสียงไม่มา/สะดุด น่าจะเป็นเรื่องอุปกรณ์เสียงหรือสิทธิ์ไมโครโฟน แจ้งมาปรับได้

## การบังคับให้ Agent ทำงานเสมอ และการปิดด้วยรหัสผู้ดูแล

ตัวติดตั้งเครื่องลูกจะติดตั้ง **Windows Service ชื่อ `RainDropAgentSvc`** ที่รันด้วยสิทธิ์ SYSTEM โดย

- **เปิด Agent อัตโนมัติทุกครั้งที่บูตเครื่อง** (Service ตั้งเป็น start= auto) โดยเปิดในเซสชันของผู้ใช้ที่ล็อกอินอยู่ ด้วย `WTSQueryUserToken` + `CreateProcessAsUser`
- **ปลุก Agent กลับภายใน ~2 วินาที** ถ้าถูกปิดด้วย End Task เพราะ Service วนตรวจทุก 2 วินาทีว่า Agent ยังทำงานอยู่
- **ผู้ใช้ทั่วไปปิด Service ไม่ได้** เพราะ Service รันเป็น SYSTEM (ต้องเป็น Administrator จึงจะ `sc stop` ได้) และ Windows ตั้งให้เปิด Service ใหม่เองถ้าล้ม
- **การปิด Agent อย่างถูกต้อง**: คลิกขวาไอคอนหยดน้ำ → "ออกจากโปรแกรม (ต้องใช้รหัสผู้ดูแล)" → ใส่รหัสให้ถูก
  Agent ส่งรหัสที่ผู้ใช้กรอกไปให้ Service ตรวจผ่าน named pipe (`RainDropAgentCtrl`) Service ตรวจ PBKDF2 เองจาก hash
  ที่ผู้ใช้ทั่วไปอ่านไม่ได้ ถ้าถูกจึงหยุดปลุกและหยุดตัวเอง (จะกลับมาทำงานอีกครั้งเมื่อบูตรอบถัดไป)
  ไม่มีการส่ง token ผ่าน environment variable หรือไฟล์สัญญาณอีกต่อไป
- **กันเดารหัส:** ลองผิดครบ 5 ครั้ง Service ล็อกชั่วคราว 5 นาที (นับและตรวจฝั่ง Service ทั้งหมด)
- **ACL ของท่อ:** อนุญาตเฉพาะ SYSTEM, Administrators และผู้ใช้ที่ล็อกอินอยู่ในเซสชันคอนโซล
  คำสั่งตั้ง/อ่าน blocklist รับเฉพาะจากโปรเซส Agent ที่ Service เปิดเอง (ตรวจ PID ของปลายท่อ)

**ตั้งรหัสผ่านตอนติดตั้ง:** ตัวติดตั้งบังคับกรอกรหัสอย่างน้อย 8 ตัวอักษร (ห้ามว่าง ไม่มีค่าเริ่มต้น `raindrop` อีกต่อไป)
โหมดเงียบต้องส่ง `/PASSWORD=`, `/BUNDLE=` และ `/BUNDLEPASSWORD=` มิฉะนั้นล้มเหลวทันที:
```
RainDrop-Agent-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /PASSWORD=MyStrongPass123 /BUNDLE=C:\deploy\PC-01.rdrop /BUNDLEPASSWORD=MyBundlePass12
```
รหัสถูกเก็บเป็น PBKDF2 (ไม่เก็บรหัสจริง) ใน `%ProgramData%\RainDrop\private\credentials.json`
ซึ่งตั้ง ACL ให้เฉพาะ SYSTEM/Administrators อ่านได้ ผู้ใช้ทั่วไปไม่มีสิทธิ์แม้แต่เปิดอ่าน
ส่วน `%ProgramData%\RainDrop\agent.json` (ไม่มีรหัสผ่าน) และ `blocklist.json` ผู้ใช้ทั่วไปอ่านได้อย่างเดียว เขียนไม่ได้

> **ขอบเขตการป้องกัน:** กันผู้ใช้ทั่วไป (นักเรียน/พนักงาน) ได้ แต่ **ไม่ได้กันผู้ที่เป็น Administrator ของเครื่อง** ซึ่งหยุด Service เองได้เสมอ — เป็นไปตามหลักของ Windows ที่เจ้าของเครื่องต้องควบคุมเครื่องตัวเองได้

## ความปลอดภัยช่องควบคุม (C2a)

- TCP 11400 ห่อด้วย `SslStream` แบบ mutual TLS ทั้งสองฝั่ง บังคับใบรับรอง client และปฏิเสธ TLS ต่ำกว่า 1.2
- เชื่อใจเฉพาะ CA ขององค์กรที่ pin ไว้ (`X509ChainPolicy.CustomRootTrust`) ไม่ใช้ Windows root store
- ใบรับรอง Master มี EKU ClientAuth, ใบรับรอง Agent มี EKU ServerAuth อายุ 1 ปี; สลับบทบาทไม่ได้
- หลัง TLS ยังมีการยืนยันตัวตนแบบ challenge/response ECDSA เดิม (C1) เป็นชั้นที่สอง แล้วส่งรายการเพิกถอนแบบมีเวอร์ชัน
- Master เก็บรายการเพิกถอนเข้ารหัส DPAPI; Agent เก็บใน `private\revocation.json` ที่ Users แก้ไม่ได้ และปฏิเสธ snapshot ย้อน version
- Audit แบบ hash chain ทั้ง Master (`%AppData%\RainDrop\audit`) และ Agent (`private\audit`) หมุนไฟล์ ~10 MiB × 5
  ตรวจด้วย `RainDrop.Master.exe --verify-audit`, `RainDrop.Agent.exe --verify-audit` หรือเมนูที่ถาดไอคอน
  audit บันทึกเฉพาะ metadata (เวลา/event/IP/ผล) ไม่บันทึกแชท คีย์ที่พิมพ์ รหัสผ่าน หรือภาพ
- `RunCommand` ที่ Agent: ค่าเริ่มต้นอนุญาตเฉพาะ URL `http/https` ที่ไม่มีอาร์กิวเมนต์; โปรแกรมต้องอยู่ใน
  `private\run-allowlist.json` (พาธเต็ม) ซึ่ง Users แก้ไม่ได้ การเปิดโปรแกรมไม่ผ่าน shell
- Agent จำกัดการเชื่อมต่อใหม่ 30 ครั้ง/IP/นาที และ handshake ล้มเหลว 8 ครั้ง/IP/นาที

### ความลับบนเครื่องลูกหลัง C2a

| ที่เก็บ | เนื้อหา | สิทธิ์ |
|---|---|---|
| `%ProgramData%\RainDrop\private\agent-cert.der` + `agent-key.pkcs8` | ใบรับรองและกุญแจลับของ Agent เครื่องนี้เท่านั้น | SYSTEM/Administrators; Users เข้าไม่ได้ |
| `%ProgramData%\RainDrop\private\ca-cert.der` | กุญแจสาธารณะของ CA (ไม่ใช่ความลับ) | SYSTEM/Administrators |
| `%ProgramData%\RainDrop\private\revocation.json`, `run-allowlist.json`, `audit\` | นโยบาย/บันทึกที่ผู้ใช้แก้ไม่ได้ | SYSTEM/Administrators |
| `%ProgramData%\RainDrop\challenge-public.pem` | กุญแจสาธารณะ challenge ของ Master | Users อ่านได้อย่างเดียว |

กุญแจลับ CA ไม่อยู่บนเครื่องลูก กุญแจ Agent ใช้เป็น client certificate ไม่ได้ (ผิด EKU) และถ้าหลุดจะปลอมได้เฉพาะเครื่องนั้น
ผู้ใช้ที่เป็น Administrator ของเครื่องยังสามารถหยุด Service/อ่านหน่วยความจำได้ เป็นขอบเขตเดิมของ Windows

## ข้อจำกัดของ Prototype และสิ่งที่ควรทำต่อ

| ข้อจำกัด | แนวทางแก้ในเวอร์ชันถัดไป |
|---|---|
| ช่องควบคุม Agent↔Master เข้ารหัส mutual TLS แล้ว (C2a) แต่ห้องชุมชน Hub ยังไม่เข้ารหัส | TLS ของ Hub ในเฟสถัดไป |
| Agent รันในเซสชันผู้ใช้ (มี Service คอยปลุกกลับ) จึงจับภาพหน้า UAC/Lock screen ไม่ได้ | การจับ secure desktop ต้องรันส่วนจับภาพใน session 0 ซึ่งซับซ้อนและอยู่นอกขอบเขตปัจจุบัน |
| ส่งภาพเต็มเฟรม JPEG ทุกครั้ง (ใช้แบนด์วิดท์มาก) | ส่งเฉพาะส่วนที่เปลี่ยน (dirty rectangles) หรือใช้ Desktop Duplication API + H.264 |
| ล็อกจอบล็อก Ctrl+Alt+Del ไม่ได้ | เป็นข้อจำกัดของ Windows |
| ประวัติแชทไม่ถูกบันทึกลงไฟล์ | บันทึกเป็นไฟล์ log แยกตามเครื่อง/วัน |
| ห้องชุมชน: ไฟล์ที่แชร์ไปก่อนหน้า คนที่เข้าทีหลังโหลดไม่ได้ (Hub เก็บแต่ข้อความ ไม่เก็บไฟล์) | ให้ Hub เก็บไฟล์ชั่วคราวและให้ดาวน์โหลดย้อนหลัง |
| ห้องชุมชน: เสียงเป็น PCM ดิบไม่ได้บีบอัด ใช้แบนด์วิดท์ ~256 kbps/คนที่พูด | บีบอัดด้วย Opus (Concentus) |
| ห้องชุมชน: ยังไม่เข้ารหัสการรับส่ง | หุ้มด้วย TLS |
| ข้อความเสียงเป็น WAV ที่ไม่บีบอัด | บีบอัดเป็น Opus/MP3 (ไฟล์เล็กลงราว 10 เท่า) แต่ต้องใช้ไลบรารีเพิ่ม เช่น NAudio + Concentus |
| ฟังข้อความเสียงได้ทีละข้อความ และไม่มีแถบเลื่อนตำแหน่ง | เปลี่ยนไปใช้ NAudio เพื่อให้มีแถบความคืบหน้า |
| ยังไม่มี | Wake-on-LAN, ส่งไฟล์, แสดงหน้าจอผู้สอนไปทุกเครื่อง (demo mode), pairing code (C2b) |

## ข้อควรระวังด้านกฎหมาย

การดูหน้าจอพนักงานหรือผู้เรียนถือเป็นการประมวลผลข้อมูลส่วนบุคคลตาม **PDPA** ควรแจ้งผู้ใช้ล่วงหน้า
และระบุไว้ในนโยบายของบริษัท Agent ตัวนี้แสดงไอคอนรูปโล่ใน System Tray ตลอดเวลาที่ทำงาน
เพื่อให้ผู้ใช้รู้ว่าเครื่องอยู่ภายใต้การดูแล
